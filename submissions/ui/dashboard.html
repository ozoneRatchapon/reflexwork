📝 คำถามที่คู่มือยังตอบไม่ได้ (KB Gap Backlog)

คำถามที่ระบบ "ไม่พบในคู่มือ" → เก็บไว้เป็นรายการให้เจ้าหน้าที่เพิ่มความรู้ · ยิ่งถามบ่อย = ยิ่งควรเพิ่มก่อน (ระบบรู้ว่าตัวเองไม่รู้อะไร)
คำถามถูกถาม (ครั้ง)ล่าสุดช่องทาง

🔧 ระบบต้นทางไหนก่อปัญหาเยอะสุด

จัดกลุ่มคำถามที่ตอบไม่ได้ตาม "ระบบต้นทาง" ที่เกี่ยวข้อง → บอกผู้บริหาร/IT ว่าควรไปแก้ที่ต้นเหตุระบบไหนก่อน · เป้าหมายสูงสุดของ ReflexWork คือทำให้คำถามพวกนี้ลดลง เพราะระบบต้นทางถูกแก้
ยังไม่มีข้อมูล — เมื่อมี gap จะจัดกลุ่มตามระบบให้
เปิดหน้ารายงานสะอาด → กด Print → Save as PDF

✅ KB Drafts รออนุมัติ (ปิด learning loop)

คำตอบที่เจ้าหน้าที่บันทึก (หรือระบบร่างอัตโนมัติจากคำถามที่ตอบไม่ได้) → รอกด อนุมัติ เพื่อแปลงเป็นหัวข้อในคู่มือ · ยิ่งใช้ คู่มือยิ่งโตจากงานประจำ ไม่ต้องมานั่งเขียนเอง
✍️ ตอบคำถามที่คู่มือยังไม่มี
กด "ตอบ" ที่รายการคำถามด้านบนเพื่อเติมคำถามให้ · เมื่ออนุมัติ คำตอบจะขึ้นในแชทภายใน ~15 วินาที พร้อมป้าย "📝 เจ้าหน้าที่ตอบ" และถอนได้ · ใส่เฉพาะข้อเท็จจริงที่ตรวจแล้ว

    

    
ยังไม่มี draft — เมื่อเจ้าหน้าที่บันทึกคำตอบ จะมาโผล่ที่นี่

  


  

    
📝 คำตอบจากเจ้าหน้าที่ที่อยู่ในแชทตอนนี้

    
อนุมัติแล้ว ยังไม่ได้รวมเข้าคู่มือหลัก · นักศึกษาเห็นพร้อมป้าย "📝 เจ้าหน้าที่ตอบ" · กด "ถอน" แล้วจะหายจากแชทภายใน ~15 วินาที

    
ยังไม่มีคำตอบจากเจ้าหน้าที่ในแชท

  


  

    
📉 หัวข้อคู่มือที่ถูก 👎 บ่อย (ควรแก้ก่อน)

    
ระบบปรับ ความน่าเชื่อถือ ของแต่ละหัวข้อในคู่มือเองจาก 👍/👎 ของผู้ใช้ (ค่าเฉลี่ยแบบถ่วงเวลา) · หัวข้อที่คนไม่พอใจบ่อย = รายการที่ควรแก้/เขียนใหม่ก่อน (ระบบรู้เองว่าข้อไหนอ่อน)

    
ยังไม่มีข้อมูล feedback — เมื่อผู้ใช้กด 👍/👎 จะมาโผล่ที่นี่
