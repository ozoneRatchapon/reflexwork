# ร่างหัวข้อคู่มือ 14 ข้อ — สำหรับเจ้าของคู่มือตรวจ (สถานะ DRAFT ไม่ขึ้นแชต)

สร้างเมื่อ 2026-11-06 จาก FAQ ทางการ <https://graduate.mahidol.ac.th/engine/structure/faq/?lang=thai> (ดึงวันนี้) สำหรับ **FAQ นักศึกษา/ผู้สมัคร 14 ข้อที่คู่มือเรายังไม่มี**
(รายการเดียวกับที่ `benchmark/field/results/002_*` ระบุว่า "ภาษาไทย 10 ใน 14 ข้อระบบตอบด้วยหัวข้อที่ไม่ตรง").

## สิ่งที่อยู่ในร่าง และสิ่งที่ไม่ใช่
- ถ้อยคำคำตอบ **คัดลอกตามต้นฉบับ ไม่เขียนเอง** (11 ข้อจาก JSON-LD ของหน้า, 3 ข้อ — 88, 89, 110 — จากส่วน HTML เพราะไม่อยู่ใน JSON-LD; รวมบรรทัดสั้นๆ ที่ต่อเข้าด้วยกัน และตัดข้อความปุ่มของหน้าเว็บออก)
- คำค้นภาษาอังกฤษ = ถ้อยคำภาษาอังกฤษของโรงเรียนเอง (`?lang=inter`) ไม่ใช่ที่เราแปล
- ต้นฉบับมีรอยต่อจากการแปลงไฟล์ เช่น "ศูนย ์ภาษา" "ช่อ ง" "ให ม่" (ช่องว่างแทรกกลางคำ) — **คงไว้ตามต้นฉบับ** เจ้าของควรแก้ในต้นฉบับ/ในหัวข้อ
- ข้อ 89: ต้นฉบับแยกเกณฑ์ตามกลุ่มรหัสนักศึกษา (59–62 / 63–66 / 67 ขึ้นไป) แต่ตัวเกณฑ์อยู่ใน PDF ที่ลิงก์ไว้ ไม่ได้อยู่ในหน้า FAQ
- หมวดหมู่ (`category`) เป็นข้อเสนอของเรา แมปเข้ากับหมวดที่มี — เจ้าของแก้ได้
- ข้อ 8 และ 20 เป็นกรณีเฉพาะ (บุคคลทั่วไป / การยกเลิกแต่งตั้งกรรมการ) ควรตรวจกลุ่มผู้อ่านก่อนขึ้นแชต
- ไฟล์ทั้งหมดเป็น `approval_status: "draft"` ในโฟลเดอร์ `docs/` จึง **ไม่ถูกสร้างเข้าดัชนีและไม่ขึ้นแชต** (ตัวสร้างดัชนีรวมเฉพาะ `approved`)

## ขั้นตอนเมื่อเจ้าของตัดสินใจแล้ว
1. ตรวจเนื้อหาแต่ละข้อกับต้นฉบับ และกลุ่มผู้อ่าน; เลือกหัวข้อที่จะขึ้น (อาจรวมกับหัวข้อเดิม แทนการเพิ่มใหม่)
2. ข้อที่อนุมัติ: ย้ายไฟล์ไป `submissions/ui/knowledge-public/` และเปลี่ยนเป็น `approval_status: "approved"`
3. `python3 submissions/build_knowledge_index.py && node scripts/gen_line_kb.mjs`
4. รันซ้ำ `node benchmark/field/official_faq_eval.mjs`, `benchmark/compare/run_all.sh` และ `node tests/pitch_claims.test.mjs` — ตัวเลขในสไลด์จะเปลี่ยน (ตั้งใจ) ต้องอัปเดตสไลด์/ชีตตาม
5. อย่า deploy ก่อนที่ผลวัดหลังอนุมัติจะไม่แย่ลงกว่าเดิมในข้อที่เคยตอบถูก
