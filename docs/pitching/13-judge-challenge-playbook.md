## 2. "ลองกับข้อมูลของผม/หน่วยงานผมได้ไหม"

**ตอบ:** "ได้ค่ะ — ถ้าให้คำถาม-คำตอบมา 3–5 ข้อ เราสร้างเว็บแชตของหน่วยงานให้ดูบนเครื่องได้เลย"
ทำหลังจบช่วง Q&A หรือที่บูธ (ใช้เวลาพิมพ์ราว 3–5 นาที ไม่ควรทำในเวลา Q&A 5 นาที)

ทดสอบแล้ว 6 พ.ย. (หน่วยงานสมมติ 3 หัวข้อ): **สร้างเว็บใช้ 0.08 วินาที** ตอบถูกจากข้อมูลใหม่ และบอก "ยังไม่มี" กับเรื่องที่ไม่มี

```bash
# 1) คัดลอกตัวอย่าง แล้วแก้ agency.json (name, title, greeting) และไฟล์ใน knowledge/ (1 ไฟล์ = 1 คำถาม-คำตอบ)
cp -R examples/library-demo /tmp/judge_pack && rm /tmp/judge_pack/knowledge/*.md
#    ทุกไฟล์ต้องมี frontmatter: title, source_url, approval_status: "approved"  (ดูรูปแบบจาก examples/library-demo/knowledge/)
# 2) สร้าง + เปิด
node scripts/new_agency.mjs /tmp/judge_pack /tmp/judge_site
cd /tmp/judge_site && python3 -m http.server 8000     # → http://localhost:8000/
```

**ระวัง (เจอจากการทดสอบจริง):**
- ในเว็บหน่วยงานใหม่ คำถามเรื่อง **หลักสูตร/การสมัครเรียน** — ทดสอบแล้วพังกับ "ทุน…", "ค่าเทอม…", "สมัครเรียนยังไง", "มีหลักสูตรอะไรบ้าง", "ปริญญาโท" — จะขึ้น "โหลดรายการหลักสูตรทางการไม่สำเร็จ" แทนที่จะค้นในข้อมูลของหน่วยงาน เพราะคำเหล่านี้พาไปทางค้นแคตตาล็อกหลักสูตร ซึ่งหน่วยงานใหม่ไม่มี (โค้ดหน้า production ก็เป็นแบบเดียวกัน) **แก้แล้วหลัง pitch (7 พ.ย.):** หน่วยงานที่ไม่มี `programmes.json` ข้ามไปค้นคู่มือของตัวเอง (`scripts/adoption_smoke.mjs` ตรวจ) — ยังไม่ deploy
- AI ปิดอยู่ในเว็บที่สร้าง → คำถามสั้น/ภาษาพูดมาก เช่น "ค่าหอเท่าไร" อาจไม่เข้าใจ ส่วน "หอพักราคาเท่าไร" ตอบได้ · แนะนำให้ใส่คำที่คนใช้ถามจริงลงในหัวข้อ/เนื้อหา
- บอตพูด "ครับ" เป็นค่าเริ่มต้น (แก้ได้ใน `persona` ของ `agency.json`)

**ถ้ากรรมการยื่น PDF หรือลิงก์เว็บ:** "การอ่าน PDF อัตโนมัติยังไม่ได้ทำ — วันนี้คนต้องแปลงเป็นคำถาม-คำตอบที่อนุมัติแล้วก่อน และนี่คือสิ่งที่เราอยากให้ AI ช่วยฝั่งหลังบ้านเป็นขั้นต่อไป"
**ห้าม** เอาข้อมูลกรรมการใส่เว็บจริง (`reflexwork.pages.dev`) — เว็บจริงเป็นคู่มือบัณฑิตวิทยาลัย และ freeze อยู่

## 2.1 "หน่วยงานอื่นใช้ได้จริงไหม" — หลักฐาน 3 ชั้น
1. **ให้เห็น (แท็บเปิดไว้ก่อนขึ้นเวที):** `node scripts/new_agency.mjs examples/library-demo /tmp/agency_demo && cd /tmp/agency_demo && python3 -m http.server 8001` → `http://localhost:8001/` — ห้องสมุดสมมติ 6 หัวข้อ ระบบเดียวกัน ข้อมูลคนละชุด ถาม "ห้องสมุดเปิดกี่โมง" ตอบจากข้อมูลห้องสมุด · ถาม "ที่จอดรถอยู่ไหน" บอกว่ายังไม่มี (ทดสอบแล้ว 7 พ.ย.) · ห้ามถามเรื่องหลักสูตร/ค่าเทอม (ข้อบกพร่องข้างบน)
2. **ทดสอบอัตโนมัติ:** `node tests/agency_pack.test.mjs` → 10/10 — ตรวจว่าเว็บที่สร้างไม่มีข้อมูลบัณฑิตวิทยาลัยติดไป · หน้าไม่เอ่ยชื่อบัณฑิตวิทยาลัย · ค่าเริ่มต้นไม่ต่อ backend/AI เลย (ต่อเมื่อหน่วยงานตั้งเอง)
3. **คู่มือนำไปใช้:** `docs/adopt.md` — 5 ขั้นตอน ค่าเริ่มต้นด้านความเป็นส่วนตัว และข้อจำกัด (เวลา/ต้นทุนในไฟล์นั้นเป็น**ประมาณการ**)

**พูดตรง ๆ:** ยังไม่มีหน่วยงานจริงแห่งที่สองใช้งาน — นั่นคือสิ่งที่เราขอ (หน่วยงานนำร่อง)

## 2.2 "ใช้ทั้งมหาวิทยาลัย ข้อมูลภายในปลอดภัยไหม หลุดไปเทรน LLM ข้างนอกไหม"

**ตอบ 30 วินาที:**
"ข้อเท็จจริงทั้งหมดอยู่ในคู่มือของหน่วยงานเอง ไม่ได้อยู่ในโมเดล — เราไม่ได้เทรนหรือ fine-tune โมเดลด้วยข้อมูลของมหาวิทยาลัยเลย
คำถามส่วนใหญ่ตอบจากคู่มือโดยไม่ส่งอะไรออกไปที่ AI · ส่วนที่ใช้ AI จะส่งแค่คำถาม กับหัวข้อคู่มือที่เกี่ยวข้องไม่เกิน 3 หัวข้อ ไม่ใช่เอกสารทั้งคลัง
ไม่มีล็อกอิน ไม่มีข้อมูลรายบุคคลในระบบ คำถามเรื่องข้อมูลส่วนตัวระบบปฏิเสธและไม่บันทึก
และสำหรับเอกสารภายใน หน่วยงานเลือกได้ 3 ระดับ: ปิด AI ทั้งหมด (ค่าเริ่มต้นของหน่วยงานใหม่) · ใช้ AI แบบองค์กรที่สัญญาไม่เอาข้อมูลไปเทรน · หรือใช้โมเดลที่รันในเครื่องของมหาวิทยาลัยเอง ข้อมูลไม่ออกไปข้างนอกเลย"

**หลักฐานในโค้ด:**
| เรื่อง | ทำจริง | ที่ไหน |
|---|---|---|
| ไม่ได้เทรนโมเดล | ข้อเท็จจริงอยู่ใน `knowledge-index.json` ค้นในเบราว์เซอร์ | `crates/reflex-wasm` |
| ส่งอะไรให้ AI | ตีความ: คำถามอย่างเดียว · เรียบเรียง: คำถาม + หัวข้อคู่มือ ≤ 3 | `chatbot.html` `groundedHybrid` (`entries.slice(0,3)`) |
| proxy เก็บอะไร | ไม่มีฐานข้อมูล · log เฉพาะรายชื่อโมเดลที่ล้มเหลว ไม่ log คำถาม | `integrations/llm-proxy/worker.mjs:212,311` |
| เก็บคำถามที่ตอบไม่ได้ | ≤ 200 ตัวอักษร ปิดอีเมล เบอร์โทร เลขยาว (ชื่อคนปิดเฉพาะหลังคำว่า "ชื่อ") | `kernel-worker/worker.mjs:320` |
| เข้าคู่มือได้เฉพาะที่อนุมัติ | builder โหมด approved-only | `submissions/build_knowledge_index.py` |
| หน่วยงานใหม่ไม่ต่อ AI | ค่าเริ่มต้นไม่มี backend/AI | `tests/agency_pack.test.mjs` |
| โมเดลในเครื่อง | proxy สำหรับ Ollama (Typhoon2 3B) | `integrations/llm-proxy/local-llm-proxy.mjs` |
| โฮสต์เองได้ | เว็บที่สร้างเป็นไฟล์ static วางบน server มหาวิทยาลัยได้ | `scripts/new_agency.mjs` |

**⚠️ ต้องเช็กก่อนตอบเรื่อง "เทรน":** ต้นแบบตอนนี้ใช้ **Gemini API ด้วย key ของทีม** — ตามเงื่อนไขของ Google, key แบบ**ฟรี** อาจให้ Google นำข้อมูลไปปรับปรุงผลิตภัณฑ์ได้ ส่วน key ที่**เปิด billing** ไม่นำไปใช้ (เช็กเงื่อนไขปัจจุบันอีกครั้ง)
- ถ้า key เป็นแบบฟรี: พูดว่า "ต้นแบบใช้ key ทดลอง ข้อมูลที่ส่งคือคู่มือที่เปิดเผยอยู่แล้วกับคำถาม — ใช้จริงจะใช้บัญชีองค์กรหรือโมเดลในมหาวิทยาลัย" **ห้ามพูดว่า "ไม่หลุดไปเทรนแน่นอน"**
- ห้ามพูด "ข้อมูลไม่ออกนอกเครื่อง" สำหรับเว็บปัจจุบัน (ไม่จริงเมื่อใช้ AI)

## 2.3 "งบดูแลรักษาเท่าไหร่ ประหยัดจริงแค่ไหน"

**ตอบ 30 วินาที:**
"ต้นทุนแบ่งเป็น 3 ส่วนค่ะ
หนึ่ง ค่าระบบ — เว็บเป็นไฟล์ static การค้นคู่มือทำในเครื่องผู้ใช้ ต้นแบบนี้ออกแบบให้รันบนแผนฟรีของ Cloudflare ได้ ค่าโฮสต์จึงใกล้ศูนย์
สอง ค่า AI — เรียกเฉพาะคำถามที่คู่มือตอบตรงไม่ได้ บนชุดทดสอบของเราตอบเองโดยไม่เรียก AI 44 จาก 52 ข้อ ถ้าประมาณการคณะละ 300 คำถามต่อวัน ส่วนที่ไม่ต้องเรียก AI คิดเป็นเงินแค่หลักไม่กี่ดอลลาร์ต่อเดือน และถ้าใช้โมเดลในมหาวิทยาลัย ค่า API เป็นศูนย์
สาม ต้นทุนหลักจริง ๆ คือ คน — เจ้าหน้าที่ที่ดูแลคู่มือ ตอบคำถามที่ระบบยังตอบไม่ได้ และอนุมัติ ไม่ต้อง retrain โมเดล
ดังนั้นสิ่งที่ประหยัดจริงไม่ใช่ค่า token แต่คือเวลาเจ้าหน้าที่ที่ต้องตอบคำถามซ้ำ ซึ่งเราจะวัดเป็นตัวเลขจริงตอนนำร่องค่ะ"

| ตัวเลข | สถานะ | ที่มา |
|---|---|---|
| ตอบเองไม่เรียก AI 44/52 (85%) | **วัดแล้ว** (ชุดเล็ก ทีมเขียนเอง) | `benchmark/compare/run_all.sh` |
| สร้างเว็บหน่วยงานใหม่ < 1 วินาที | **วัดแล้ว** | `scripts/new_agency.mjs` |
| ค่า token ที่ไม่ต้องจ่าย ~$3/เดือน/คณะ | **ประมาณการ** (300 คำถาม/วัน × 80% × 1,500 token × $0.30/1M) | `60-impact-numbers.md` |
| เวลาเจ้าหน้าที่ ~12 ชม.คน/วัน/คณะ ช่วงพีก | **ประมาณการ** (240 คำถาม × 3 นาที) | `60-impact-numbers.md` |
| เขียนหัวข้อคู่มือ 5–10 นาที/ข้อ | **ประมาณการ** | `docs/adopt.md` |

- ถ้าถูกถามตัวเลข: บอก**สมมติฐาน + สูตร** ก่อนตัวเลขเสมอ · ห้ามพูด "ประหยัด 80%" หรือ "หลายเท่าตัว" เป็นผลวัด
- `40-qa-bank.md` Q4 เขียน "หลักสิบดอลลาร์/เดือน/คณะ" แต่ `60-impact-numbers.md` คำนวณได้ ~$3 — **ใช้ ~$3 ตามสูตร** · ราคา $0.30/1M token เป็นค่าสมมติ ไม่ได้เช็กราคาวันนี้
- ยังไม่ได้ยืนยันว่าบัญชี Cloudflare/Gemini ตอนนี้เป็นแผนฟรีทั้งหมด → พูดว่า "ออกแบบให้รันบนแผนฟรีได้" ไม่ใช่ "วันนี้ค่าใช้จ่ายเป็นศูนย์"

## 2.4 "ถ้าเอกสาร 2 ฉบับขัดกัน (ประกาศเก่า vs ใหม่) ระบบทำยังไง"

**ตอบ 30 วินาที:**
"ระบบไม่เลือกเองแบบเงียบ ๆ ค่ะ มี 3 ชั้น
หนึ่ง ประกาศที่ต่างกันตามปีหรือภาคเรียน เราติดป้ายปีและภาคไว้ ถ้าผู้ใช้ไม่ระบุ ระบบจะถามกลับว่าหมายถึงปีไหน ภาคไหน — ถ้าระบุมา ก็ตอบฉบับนั้น
สอง ถ้าสองหัวข้อคะแนนใกล้กันจนแยกไม่ออก ระบบให้ผู้ใช้เลือก ไม่ตอบข้อใดข้อหนึ่งเอง
สาม ทุกคำตอบบอกที่มา ปีของประกาศ และวันที่เก็บข้อมูล ถ้าข้อมูลเก่าจะมีคำเตือนให้ตรวจที่ต้นทาง
ส่วนการตัดสินว่าฉบับไหนใช้แทนฉบับไหน เป็นหน้าที่ของคน — ทุกหัวข้อต้องอนุมัติก่อนขึ้นระบบ และถอนออกได้ทันที"

**สาธิต (ทดสอบบนเว็บจริงแล้ว 7 พ.ย.):** ถาม **"ลงทะเบียนเมื่อไหร่"** → "เรื่องนี้คำตอบไม่เหมือนกันในแต่ละปีการศึกษาและภาคเรียน — หมายถึงอันไหน?" + ตัวเลือก ภาคต้น / ภาคปลาย / ฤดูร้อน 2569 · ถาม "ลงทะเบียนภาคปลาย 2569" → ตอบฉบับนั้นตรง ๆ

## 2.5 "วัดยังไงว่า AI ไม่มั่ว / ไม่มโนข้อมูลเลยจริง ๆ"

**หลัก:** แยก 2 แบบของ "ตอบผิด" — (ก) **AI แต่งข้อเท็จจริงขึ้นเอง** ซึ่งเราออกแบบกันไว้ และ (ข) **ค้นได้หัวข้อผิด** ซึ่งเป็นจุดอ่อนจริงที่เราวัดและเปิดเผย · **ห้ามตอบว่า "ไม่มั่วเลย 100%"**

**ตอบ 40 วินาที:**
"เราแยกความผิดพลาดเป็น 2 แบบค่ะ
แบบแรก AI แต่งข้อมูลขึ้นเอง — ข้อเท็จจริงทุกตัวมาจากคู่มือ AI แค่เรียบเรียง และมีตัวตรวจ: ทุกประโยคที่ AI เขียน ถ้ามีตัวเลข วันที่ เดือน หรือชื่อเฉพาะที่ไม่มีในต้นฉบับ ประโยคนั้นถูกตัดทิ้ง ถ้าไม่เหลือ ระบบแสดงข้อความคู่มือแทน และคำถามส่วนใหญ่ไม่เรียก AI เลย
แบบที่สอง ซึ่งเป็นจุดอ่อนจริงของเรา คือค้นได้หัวข้อผิด — เราวัดแยกไว้: คำถาม FAQ จริงภาษาไทยที่คู่มือมี ตอบถูก 94% ผิด 6% ภาษาอังกฤษถูก 49% และคำถามที่คู่มือไม่มี ระบบยังตอบด้วยหัวข้อใกล้เคียง 10 จาก 14 ข้อ
