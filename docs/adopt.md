> สถานะจริง (2026-11-14): หน่วยงานอื่นติดตั้งได้ด้วยคำสั่งเดียวจาก **ชุดข้อมูลของหน่วยงาน (pack)** ทดสอบกับ **หน่วยงานสมมติ** (ห้องสมุดตัวอย่าง คู่มือ 6 ข้อ)
> และกับ **ฉบับร่างของหน่วยงานจริงแห่งที่สอง**: วิทยาลัยดุริยางคศิลป์ (`packs/music-college`, 38 หัวข้อจากเว็บไซต์สาธารณะของวิทยาลัย **ยังไม่มีหัวข้อใดได้รับอนุมัติจากวิทยาลัย**)
> ทั้งสองผ่าน `node scripts/adoption_smoke.mjs` — ดูหัวข้อ "สิ่งที่ยังไม่ได้ทำ"

## สิ่งที่ต้องมี
| ต้องมี | รายละเอียด |
|---|---|
| ข้อมูลทางการของหน่วยงาน | FAQ หรือประกาศที่หน่วยงานรับรองแล้ว — **ระบบตอบเฉพาะสิ่งที่อยู่ในนี้** ไม่เดา |
| คนอนุมัติข้อมูล | ผู้รับผิดชอบหนึ่งคนที่ตั้ง `approval_status: "approved"` ในแต่ละหัวข้อ (หัวข้อที่ยังไม่อนุมัติจะไม่ถูกเผยแพร่) |
| ที่โฮสต์เว็บแบบ static | Cloudflare Pages, GitHub Pages, nginx ฯลฯ ไม่ต้องมีเซิร์ฟเวอร์และไม่ต้องมีฐานข้อมูล |
| คนที่รันคำสั่งได้ | Node 20+ และ Python 3 (ครั้งเดียวตอนสร้างเว็บ) |

ไม่ต้องมี: บัญชีผู้ใช้, API key ของโมเดล, แคตตาล็อกหลักสูตร, ฐานข้อมูล

## 5 ขั้นตอน (และขั้นที่ 6 ถ้าต้องการ LINE)
1. **คัดลอกตัวอย่าง** `examples/library-demo/` เป็นโฟลเดอร์ของคุณ (เช่น `my-unit/`)
2. **เขียนหัวข้อ** ไฟล์ละหนึ่งเรื่องใน `my-unit/knowledge/*.md` รูปแบบ:
   ```
   ---
   title: "เวลาเปิดทำการของห้องสมุด"
   category: "library"
   source_type: "official_faq"
   source_name: "ชื่อแหล่งข้อมูลของหน่วยงาน"
   source_url: "https://หน่วยงาน.ac.th/faq"
   language: "th"
   approval_status: "approved"
   ---
   ## เวลาเปิดทำการของห้องสมุด

   คำค้นภาษาอังกฤษ: library hours open close

   คำตอบที่หน่วยงานรับรอง (ตัวเลข วันที่ ต้องตรงกับต้นฉบับ)
   ```
   เขียนหัวข้อให้ **ตรงกับวิธีที่คนถาม** ("ยืมหนังสือได้กี่เล่ม") เพราะการค้นให้น้ำหนักกับชื่อหัวข้อ และอย่าเติมคำค้นยาวๆ (ทดลองแล้วพบว่าคำค้นเยอะทำให้คะแนนหัวข้อเจือจางและภาษาไทยแย่ลง — ดู `docs/pitching/100-evidence-and-score.md`)

   **ประกาศเก่า / ใหม่ (ไม่บังคับ)** ใส่ในส่วนหัวของไฟล์ได้ 3 ช่อง
   - `supersedes: "ชื่อไฟล์เก่า, ชื่อไฟล์อื่น"` (ไม่ต้องใส่ `.md`): ฉบับนี้ใช้แทนไฟล์เหล่านั้น ไฟล์เก่าจะ**ไม่ถูกเผยแพร่** และคำตอบฉบับใหม่ขึ้นว่า "🔁 ฉบับนี้ใช้แทน: …" ถ้าฉบับใหม่ยังไม่อนุมัติ ฉบับเก่ายังใช้ต่อ
   - `valid_from: "2026-08-01"` / `valid_to: "2027-07-31"` (ปี ค.ศ. รูปแบบ YYYY-MM-DD): ช่วงที่ประกาศมีผล ถ้าเลย `valid_to` แล้ว คำตอบจะขึ้นคำเตือนว่าอาจไม่เป็นปัจจุบัน
   - ชื่อไฟล์ที่ไม่มีอยู่, ฉบับที่แทนตัวเอง, การแทนวนกลับ หรือวันที่ผิดรูปแบบ → สร้างเว็บไม่ผ่านและบอกว่าไฟล์ไหนผิด
3. **แก้ `my-unit/agency.json`**: ชื่อหน่วยงาน หัวเรื่อง ข้อความต้อนรับ ตัวอย่างคำถาม (ชิป) ลิงก์ติดต่อเจ้าหน้าที่ ลิงก์ FAQ ทางการ และ (ถ้ามี) `it: {name, phone, email}` สำหรับกล่องปัญหาบัญชี/ระบบ — ไม่ใส่ `it` จะใช้ลิงก์ติดต่อเจ้าหน้าที่แทน (ต้องมี `name`, `title`, `greeting`) ข้อมูลใดที่ไม่ใส่ จะไม่มีปุ่มนั้น **ไม่ได้ย้อนไปใช้ค่าของบัณฑิตวิทยาลัย**
   - รายชื่อในเนื้อคำตอบ (เช่น สาขา) ให้เขียนเป็น `หัวข้อ: ชื่อ1, ชื่อ2, ชื่อ3` บรรทัดเดียว คั่นด้วยจุลภาค อย่างน้อย 3 ชื่อ ใส่ชื่ออังกฤษในวงเล็บได้ เช่น `แจ๊ส (Jazz)` ระบบจึงตอบคำถาม "มี X ไหม" จากรายชื่อนี้ได้ แม้ X ไม่อยู่ในหัวข้อ
   - (ไม่บังคับ) `vocab`: คำที่ระบบใช้ตีความคำถาม (คำเรียกรอบรับสมัคร ภาคเรียน ฯลฯ) ใส่**เฉพาะคีย์ที่ต้องการเปลี่ยน** คีย์ที่ไม่ใส่ใช้ค่าเริ่มต้นจาก `packs/graduate-school/vocab.json` เช่น `"vocab": {"words": {"round_first": "รอบแรก"}}` รูปแบบ regex ต้องใส่ทั้ง `src` และ `flags` คีย์ที่ไม่มีอยู่ หรือ regex ที่คอมไพล์ไม่ได้ → สร้างเว็บไม่ผ่านและบอกชื่อคีย์
4. **สร้างเว็บ**: `node scripts/new_agency.mjs my-unit /path/to/site` (ใช้เวลาไม่ถึงวินาทีกับ 6 หัวข้อ; โฟลเดอร์ปลายทางต้องว่าง)
   - ทุกครั้งที่สร้างจะตรวจคุณภาพหัวข้อให้ (`pack-lint`, เตือนเท่านั้น ไม่หยุดการสร้าง): หัวข้อซ้ำหรือคล้ายกันจนแย่งคำถามกัน บรรทัดคำค้นที่ว่าง และวันที่ในคำตอบที่เลย `valid_to` ดูหัวข้อที่หมดอายุหรือใกล้หมด (7 วัน) ได้ด้วย `cargo run -q -p pack-tools --bin pack-expiry -- my-unit`
   - ให้ผู้รับผิดชอบตรวจก่อนอนุมัติ: `node scripts/new_agency.mjs my-unit /tmp/preview --draft` (รวมหัวข้อที่ยังไม่อนุมัติ ใช้ดูในเครื่องเท่านั้น ห้ามเผยแพร่) จะได้ `/tmp/preview/review.html` ด้วย: ทุกหัวข้อพร้อมคำตอบ แหล่งที่มา วันหมดอายุ และสถานะ ย่อหน้าที่แชทจะไม่แสดงถูกขีดเส้นไว้พร้อมเหตุผล ผู้รับผิดชอบติ๊ก "อนุมัติ" แล้วกดดาวน์โหลด `approve.patch` ส่งให้ทีมพัฒนารัน `git apply approve.patch` ที่ราก repository (หน้านี้ไม่ส่งข้อมูลออกไปไหน; ต้องมี Rust toolchain เพราะสร้างด้วย `crates/pack-tools`)
5. **ทดสอบและเผยแพร่**
   - ลองในเครื่อง: `cd /path/to/site && python3 -m http.server 8000`
   - ตรวจว่าเป็นของหน่วยงานคุณจริง: `node scripts/adoption_smoke.mjs /path/to/site` (ต้องมี Chrome)
   - บันทึกเส้นทางคำตอบของหน่วยงานคุณไว้เทียบทีหลัง (golden ของ pack): `cargo run -q -p pack-tools --bin pack-golden -- my-unit /path/to/site benchmark/golden/<id>/route.json --write --today YYYY-MM-DD` จะบันทึกว่าแต่ละคำถาม (ตัวอย่างคำถาม, `questions.txt`, `expected.json`, ชื่อหัวข้อและคำค้น และคำถามทั่วไปที่ทุกหน่วยงานมี เช่น ทักทาย ถามนอกเรื่อง) ถูกตอบด้วยทางไหนและหัวข้อใด ครั้งต่อไปรันคำสั่งเดิมโดยไม่ใส่ `--write` เพื่อตรวจ ถ้าต่างจะบอกทีละคำถาม (แก้หัวข้อโดยตั้งใจ? บันทึกใหม่ด้วย `--write`) ห้ามใช้ golden ของบัณฑิตวิทยาลัยแทน
   - เผยแพร่: อัปโหลดโฟลเดอร์ขึ้นที่โฮสต์ใดก็ได้ เช่น `npx wrangler pages deploy /path/to/site`
   - Content-Security-Policy: เว็บที่สร้างไม่มีไฟล์ `_headers` ของเรา (CSP ของเราผูกกับ worker ของบัณฑิตวิทยาลัย) ถ้าหน่วยงานตั้ง CSP เอง ต้องมี `'wasm-unsafe-eval'` และ hash ของสคริปต์ในหน้าใน `script-src` และใส่ `kernelApi` / `llmApi` ของหน่วยงานใน `connect-src` (ดูตัวอย่างจาก `crates/pages-csp/src/policy.rs`)
6. **(ถ้าต้องการ) LINE และ kernel ของหน่วยงาน**: `node scripts/new_agency.mjs my-unit /path/to/site --with-line --with-kernel` จะเขียน `/path/to/site.workers/` (อยู่ข้างโฟลเดอร์เว็บ จึงไม่ถูกเผยแพร่ไปกับเว็บ)
   - `line/`: `worker.mjs` (ใช้โค้ด LINE ชุดเดียวกับบัณฑิตวิทยาลัย คือ `integrations/line-worker/app.mjs`), `kb-data.mjs` (คู่มือของหน่วยงานคุณ พร้อมคำทักทายและตัวอย่างคำถามจาก `persona` / `examples` ใน `agency.json` บอท LINE จึงไม่แนะนำตัวว่าเป็นบัณฑิตวิทยาลัย) และ `wrangler.toml`
   - `kernel/`: `wrangler.toml` ของ kernel (นับคำถาม บันทึกคำถามที่ตอบไม่ได้ โหวต) บนฐานข้อมูล D1 ชื่อ `reflexwork-<id>` ของหน่วยงานเอง
   - ทุกค่าที่หน่วยงานต้องสร้างหรือเลือกเองเป็น `REPLACE_...` (โฮสต์ของ kernel, LLM proxy, เว็บ และ id ของ D1) คำสั่งจะพิมพ์รายการให้ ไม่มี id หรือ URL ของบัณฑิตวิทยาลัยติดไปด้วย และไม่มีการ deploy (`tests/line_pack.test.mjs` ตรวจทั้งหมดนี้)
   - ข้อควรรู้: LLM proxy ของเรา (`integrations/llm-proxy`) ยังเขียน prompt ในนามบัณฑิตวิทยาลัย หน่วยงานที่จะเปิด AI ต้องใช้ proxy ของตัวเองที่ prompt เป็นชื่อหน่วยงานตัวเอง

## ค่าเริ่มต้นด้านความเป็นส่วนตัว
หน่วยงานอื่น **ไม่เรียกเซิร์ฟเวอร์ของเราเลย** ตามค่าเริ่มต้น: ไม่มี kernel (บันทึกคำถามที่ตอบไม่ได้, โหวต) และไม่มี AI proxy การค้นคู่มือทำในเบราว์เซอร์ของผู้ใช้ทั้งหมด (`adoption_smoke` ตรวจว่าไม่มีคำขอออกนอกเว็บ) ถ้าต้องการบันทึกช่องว่างหรือให้ AI ช่วยเรียบเรียง ต้องตั้ง `kernelApi` / `llmApi` ใน `agency.json` เป็นของหน่วยงานเอง (คู่มือติดตั้ง worker อยู่ใน `integrations/` และ `docs/production-hardening-runbook.md`) — เมื่อเปิด AI ข้อความคำถามจะถูกส่งไปยังบริการโมเดลที่เลือก ต้องทบทวน PDPA ก่อน

## ตรวจคุณภาพก่อนเปิดใช้
- ทดสอบด้วยคำถามจริงอย่างน้อย 30 ข้อที่นักศึกษา/ผู้ใช้ของคุณถามบ่อย (แก้ `benchmark/coverage/beginner_questions.txt` แล้วรัน `node scripts/coverage_probe.mjs --url ...`) ดูว่ากี่ข้อ "ไม่เข้าใจ" แล้วเติมหัวข้อ
- ให้เจ้าของข้อมูลอ่านคำตอบทุกข้อที่ระบบจะแสดง (ตัวเลข/วันที่ต้องตรงกับต้นฉบับ)
- ทดสอบกับผู้ใช้จริงอย่างน้อย 3–5 คน
- ทบทวน PDPA ถ้าจะเปิด backend หรือ AI

## สิ่งที่ยังไม่ได้ทำ / ข้อจำกัดที่รู้
- **หน่วยงานจริงแห่งที่สองยังเป็นฉบับร่าง**: วิทยาลัยดุริยางคศิลป์มี 38 หัวข้อที่ทีมร่างจากเว็บไซต์ของวิทยาลัย (`packs/music-college`) ยังไม่มีผู้อนุมัติ ยังไม่มีคำถามจริงจากผู้ใช้ และยังไม่ได้เผยแพร่ ผลทดสอบมาจากคำถามที่ทีมเขียนเอง (95 ข้อตอบถูกหัวข้อ ดู `packs/music-college/README.md`)
- **ตัวช่วยเลือกหลักสูตรและการ์ดหลักสูตรเป็นของบัณฑิตวิทยาลัย** (ใช้แคตตาล็อกและโครงหน้าเว็บของเขา) หน่วยงานอื่นที่มีแคตตาล็อกของตัวเองต้องทำ crawler/รูปแบบข้อมูลเอง — ถ้าไม่มี ฟีเจอร์นี้ปิดไว้โดยอัตโนมัติ
- **ภาษาอังกฤษ**: เข้าใจคำถามอังกฤษ แต่ตอบเป็นภาษาของข้อมูลที่ใส่ และความแม่นยำบนคำถามอังกฤษราว 50% (ภาพรวมใน `docs/pitching/100-evidence-and-score.md`)
- ช่องทาง LINE: สร้างจาก pack ได้แล้ว (`--with-line`) แต่ยังไม่เคยต่อกับบัญชี LINE ของหน่วยงานอื่นจริง และ LLM proxy ยังเป็นของบัณฑิตวิทยาลัย (ดูขั้นที่ 6)
- ยังไม่มี login/ข้อมูลเฉพาะตัว (เป็นแนวคิด ต้องได้รับอนุญาตจากเจ้าของระบบและผ่าน PDPA)
- ไฟล์ `chatbot.html` ยังมีค่าเริ่มต้นของบัณฑิตวิทยาลัยฝังอยู่ในโค้ด (ถูกแทนด้วย `agency.json` ตอนเริ่มทำงาน); `tests/agency_pack.test.mjs` ตรวจว่าไม่มีที่อื่นรั่ว
