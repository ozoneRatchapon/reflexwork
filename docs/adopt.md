# นำ ReflexWork ไปใช้ในหน่วยงานของคุณ

> สถานะจริง (ทดสอบ 2026-11-03): หน่วยงานอื่นติดตั้งได้ด้วยคำสั่งเดียวจาก **ชุดข้อมูลของหน่วยงาน (pack)** ทดสอบกับ **หน่วยงานสมมติ** (ห้องสมุดตัวอย่าง คู่มือ 6 ข้อ) แล้วผ่าน
> `node scripts/adoption_smoke.mjs`. **ยังไม่ได้ทดสอบกับหน่วยงานจริงแห่งที่สอง** — ดูหัวข้อ "สิ่งที่ยังไม่ได้ทำ"

## สิ่งที่ต้องมี
| ต้องมี | รายละเอียด |
|---|---|
| ข้อมูลทางการของหน่วยงาน | FAQ หรือประกาศที่หน่วยงานรับรองแล้ว — **ระบบตอบเฉพาะสิ่งที่อยู่ในนี้** ไม่เดา |
| คนอนุมัติข้อมูล | ผู้รับผิดชอบหนึ่งคนที่ตั้ง `approval_status: "approved"` ในแต่ละหัวข้อ (หัวข้อที่ยังไม่อนุมัติจะไม่ถูกเผยแพร่) |
| ที่โฮสต์เว็บแบบ static | Cloudflare Pages, GitHub Pages, nginx ฯลฯ ไม่ต้องมีเซิร์ฟเวอร์และไม่ต้องมีฐานข้อมูล |
| คนที่รันคำสั่งได้ | Node 20+ และ Python 3 (ครั้งเดียวตอนสร้างเว็บ) |

ไม่ต้องมี: บัญชีผู้ใช้, API key ของโมเดล, แคตตาล็อกหลักสูตร, ฐานข้อมูล

## 5 ขั้นตอน
1. **คัดลอกตัวอย่าง** `examples/library-demo/` เป็นโฟลเดอร์ของคุณ (เช่น `my-unit/`)
2. **เขียนหัวข้อ** ไฟล์ละหนึ่งเรื่องใน `my-unit/knowledge/*.md` รูปแบบ:
   ```
   ---
   title: "เวลาเปิดทำการของห้องสมุด"
   category: "library"
   source_type: "official_faq"
   source_name: "ชื่อแหล่งข้อมูลของหน่วยงาน"
   source_url: "https://หน่วยงาน.ac.th/faq"
   language: "th"
   approval_status: "approved"
   ---
   ## เวลาเปิดทำการของห้องสมุด

   คำค้นภาษาอังกฤษ: library hours open close

   คำตอบที่หน่วยงานรับรอง (ตัวเลข วันที่ ต้องตรงกับต้นฉบับ)
   ```
   เขียนหัวข้อให้ **ตรงกับวิธีที่คนถาม** ("ยืมหนังสือได้กี่เล่ม") เพราะการค้นให้น้ำหนักกับชื่อหัวข้อ และอย่าเติมคำค้นยาวๆ (ทดลองแล้วพบว่าคำค้นเยอะทำให้คะแนนหัวข้อเจือจางและภาษาไทยแย่ลง — ดู `docs/pitching/100-evidence-and-score.md`)
3. **แก้ `my-unit/agency.json`**: ชื่อหน่วยงาน หัวเรื่อง ข้อความต้อนรับ ตัวอย่างคำถาม (ชิป) ลิงก์ติดต่อเจ้าหน้าที่ และลิงก์ FAQ ทางการ (ต้องมี `name`, `title`, `greeting`) ข้อมูลใดที่ไม่ใส่ จะไม่มีปุ่มนั้น **ไม่ได้ย้อนไปใช้ค่าของบัณฑิตวิทยาลัย**
4. **สร้างเว็บ**: `node scripts/new_agency.mjs my-unit /path/to/site` (ใช้เวลาไม่ถึงวินาทีกับ 6 หัวข้อ; โฟลเดอร์ปลายทางต้องว่าง)
5. **ทดสอบและเผยแพร่**
   - ลองในเครื่อง: `cd /path/to/site && python3 -m http.server 8000`
   - ตรวจว่าเป็นของหน่วยงานคุณจริง: `node scripts/adoption_smoke.mjs /path/to/site` (ต้องมี Chrome)
   - เผยแพร่: อัปโหลดโฟลเดอร์ขึ้นที่โฮสต์ใดก็ได้ เช่น `npx wrangler pages deploy /path/to/site`

## ค่าเริ่มต้นด้านความเป็นส่วนตัว
หน่วยงานอื่น **ไม่เรียกเซิร์ฟเวอร์ของเราเลย** ตามค่าเริ่มต้น: ไม่มี kernel (บันทึกคำถามที่ตอบไม่ได้, โหวต) และไม่มี AI proxy การค้นคู่มือทำในเบราว์เซอร์ของผู้ใช้ทั้งหมด (`adoption_smoke` ตรวจว่าไม่มีคำขอออกนอกเว็บ) ถ้าต้องการบันทึกช่องว่างหรือให้ AI ช่วยเรียบเรียง ต้องตั้ง `kernelApi` / `llmApi` ใน `agency.json` เป็นของหน่วยงานเอง (คู่มือติดตั้ง worker อยู่ใน `integrations/` และ `docs/production-hardening-runbook.md`) — เมื่อเปิด AI ข้อความคำถามจะถูกส่งไปยังบริการโมเดลที่เลือก ต้องทบทวน PDPA ก่อน

## เวลาและต้นทุน (ประมาณการ — ยังไม่ได้วัดกับหน่วยงานจริง)

|---|---|---|

| เขียนหัวข้อ | — | งานหลักอยู่ตรงนี้: คู่มือ FAQ ที่มีอยู่แล้วแปลงเป็นหัวข้อได้ประมาณ 5–10 นาที/ข้อ; หัวข้อที่ต้องให้เจ้าของตรวจนานกว่า |
| ตั้งค่า agency.json | — | ประมาณครึ่งชั่วโมง |
| ค่าโฮสต์ | — | ไฟล์ static: ต้นทุนใกล้ศูนย์บนบริการฟรี (ตัวเลขจริงขึ้นกับผู้ให้บริการ) |
| ผู้ดูแลต่อเนื่อง | — | หนึ่งคนที่ตรวจรายการ "คำถามที่ตอบไม่ได้" และเติมหัวข้อ (ต้องมี backend ถ้าอยากได้รายการนี้อัตโนมัติ) |

## ตรวจคุณภาพก่อนเปิดใช้
- ทดสอบด้วยคำถามจริงอย่างน้อย 30 ข้อที่นักศึกษา/ผู้ใช้ของคุณถามบ่อย (แก้ `benchmark/coverage/beginner_questions.txt` แล้วรัน `node scripts/coverage_probe.mjs --url ...`) ดูว่ากี่ข้อ "ไม่เข้าใจ" แล้วเติมหัวข้อ
- ให้เจ้าของข้อมูลอ่านคำตอบทุกข้อที่ระบบจะแสดง (ตัวเลข/วันที่ต้องตรงกับต้นฉบับ)
- ทดสอบกับผู้ใช้จริงอย่างน้อย 3–5 คน
- ทบทวน PDPA ถ้าจะเปิด backend หรือ AI

## สิ่งที่ยังไม่ได้ทำ / ข้อจำกัดที่รู้
- **ยังไม่ได้ทดสอบกับหน่วยงานจริงแห่งที่สอง** ผลที่ได้มาจากหน่วยงานสมมติที่ทีมเขียนเอง (หัวข้อง่าย)
- **ตัวช่วยเลือกหลักสูตรและการ์ดหลักสูตรเป็นของบัณฑิตวิทยาลัย** (ใช้แคตตาล็อกและโครงหน้าเว็บของเขา) หน่วยงานอื่นที่มีแคตตาล็อกของตัวเองต้องทำ crawler/รูปแบบข้อมูลเอง — ถ้าไม่มี ฟีเจอร์นี้ปิดไว้โดยอัตโนมัติ
- **ภาษาอังกฤษ**: เข้าใจคำถามอังกฤษ แต่ตอบเป็นภาษาของข้อมูลที่ใส่ และความแม่นยำบนคำถามอังกฤษราว 50% (ภาพรวมใน `docs/pitching/100-evidence-and-score.md`)
- ช่องทาง LINE ใช้สำเนาคู่มือแยก (`integrations/line-worker/`) ยังไม่ได้ผูกกับ pack
- ยังไม่มี login/ข้อมูลเฉพาะตัว (เป็นแนวคิด ต้องได้รับอนุญาตจากเจ้าของระบบและผ่าน PDPA)
- ไฟล์ `chatbot.html` ยังมีค่าเริ่มต้นของบัณฑิตวิทยาลัยฝังอยู่ในโค้ด (ถูกแทนด้วย `agency.json` ตอนเริ่มทำงาน); `tests/agency_pack.test.mjs` ตรวจว่าไม่มีที่อื่นรั่ว
